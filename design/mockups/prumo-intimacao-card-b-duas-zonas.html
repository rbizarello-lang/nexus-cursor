Direção B · Duas zonas de leitura: o que veio × o que eu anotei

A linha deixa de ser uma coluna única onde objeto, decisão e notas disputam a mesma meia largura. Em tela larga ela vira cinco faixas: situação, identidade (operação, parte, CNJ, classe, esteira), Tribunal (objeto e, logo abaixo, a decisão), Minhas notas (todas as notas curtas empilhadas, com marcador) e prazo (data única, contagem, alerta de embargos, Imp./Compl. e a peça no pé). O conteúdo externo e o interno ficam lado a lado, separados por um fio e por uma faixa levíssima, e cada zona tem altura máxima de ~4 linhas. Não há expansão inline: o texto completo continua na gaveta, que a linha inteira abre.

Por que "expirado" some do card

Toda intimação aberta há mais de 10 dias úteis (SCALTECH está aberta desde 25/08) mostraria "expirado" até o fim do prazo principal: em muitas linhas, sempre sem ação possível, o que treina o olho a ignorar a coluna. Quem precisa do histórico abre a gaveta, onde a régua de CxRuler continua mostrando "Emb. decl. · expirado". O alerta também sobrevive ao prazo principal: SUPERMERCADOS BOM PREÇO está em "Vencidas" (final há 2 dias) e ainda mostra o chip âmbar "Emb. 13/10 · 2 du", porque os embargos podem restaurar a discussão. E CLICKLOG tem embargos (21/10) depois do final (13/10): a data do pé mostra isso sem texto extra, e o tooltip diz "depois do final".

7Cabeçalho de colunas (.cx-list-h)

Decisão: mudar, não eliminar

O cabeçalho é o único lugar onde o nome das zonas custa zero linhas por intimação. Ele passa de "Parte · evento · notas | Processo | Operação | Imp. | Compl. | Prazo" para:

  • ≥ 1480 px: PARTE · PROCESSO · ESTEIRA | TRIBUNAL objeto · decisão | MINHAS NOTAS (em dourado, sobre a mesma faixa das linhas) | PRAZO · EMBARGOS … IMP. COMPL.
  • 860–1479 px: PARTE · PROCESSO | TRIBUNAL · minhas notas | PRAZO.
  • ≤ 859 px: oculto (como hoje). Os rótulos "DECISÃO" e "NOTAS" ficam inline na linha.

Por que não eliminar

Sem cabeçalho, a leitura "esquerda = tribunal, direita = eu" dependeria de rótulos repetidos em cada linha (uma linha a mais por intimação). Com o cabeçalho, a faixa dourada contínua e o fio vertical bastam: o olho aprende a zona uma vez. O custo é uma barra de ~30 px, que o app já tinha.

9Notas de implementação (para portar para CxIntimRow)

9.1 · Funções novas (todas puras; ficam junto dos helpers de src/edition-claude.jsx, ~linha 340)

/* Número do processo SEMPRE em CNJ (NNNNNNN-DD.AAAA.J.TR.OOOO). Só formata se houver 20 dígitos;
   senão devolve como veio. Exibição e cópia; o dado gravado não muda. */
function cxProcFmt(num) {
  const d = String(num || '').replace(/\D/g, '');
  if (d.length !== 20) return num || '—';
  return d.slice(0, 7) + '-' + d.slice(7, 9) + '.' + d.slice(9, 13) + '.' + d.slice(13, 14) + '.' + d.slice(14, 16) + '.' + d.slice(16);
}
/* CxProc passa a chamar cxProcFmt primeiro: Quadro, Hoje, Mesa, Foco etc. ganham o número uniforme de graça. */
function CxProc({ num, uf }) {
  const f = cxProcFmt(num);
  const m = /^(\d{7}-\d{2})(\.\d{4}\.\d\.\d{2}\.\d{4})$/.exec(f);
  return <span className="cx-proc">{uf ? <span className="cx-uf">{uf}</span> : null}{m ? <>{m[1]}<span className="cx-d">{m[2]}</span></> : f}</span>;
}
/* No botão de copiar da linha: cxCopy(cxProcFmt(intim.processNumber)). A busca continua por dígitos (cxNorm/dig). */

/* Faixa do alerta de embargos → { date, du, tone } | null.
   tone: 'calm' (> 3 du) · 'warn' (1–3 du) · 'today'. Expirado, resolvida/analisada ou sem dateStart → null. */
function cxEmbargos(intim) {
  if (!cxIsOpen(intim) || !intim.dateStart) return null;
  const date = addBusinessDays(toDayKey(intim.dateStart), 10);          // mesma conta de CxRuler
  const dd = daysUntil(date);
  if (dd === null || dd < 0) return null;
  if (dd === 0) return { date, du: 0, tone: 'today' };
  const du = cxBizUntil(date);
  return { date, du, tone: du <= 3 ? 'warn' : 'calm' };
}

/* Duas linhas do prazo. Linha 1 = data única (tom de cxDue). Linha 2 = informação NOVA. */
function cxPrazoLinhas(intim) {
  const ra = intim.responseAction;
  if (ra) return { tone: 'done', l1: '✓ ' + cxDM(ra.respondedAt), l2: 'atuação registrada' };
  if (!intim.dateDeadline) return { tone: 'none', l1: '—', l2: 'prazo fechado' };
  const dd = daysUntil(intim.dateDeadline), d = cxDate(intim.dateDeadline);
  const l1 = cxCap(CX_DOW[d.getDay()]) + ' ' + cxDM(intim.dateDeadline);
  const tone = cxDue(dd, intim.dateDeadline).tone;                         // late · today · soon · later
  let l2;
  if (dd < -1) l2 = 'há ' + dd * -1 + ' dias'; else if (dd === -1) l2 = 'ontem';
  else if (dd === 0) l2 = 'hoje'; else if (dd === 1) l2 = 'amanhã';
  else { const u = cxBizUntil(intim.dateDeadline); l2 = <>em {dd} dias<span className="du"> · {u} {u === 1 ? 'útil' : 'úteis'}</span></>; }   // .du some no celular
  return { tone, l1, l2 };
}

/* Orçamento de linhas das zonas. Só decide a DISTRIBUIÇÃO; o -webkit-line-clamp é a rede de segurança,
   então um erro de estimativa custa no máximo uma linha a mais ou a menos. cpl = caracteres por linha. */
const cxLn = (t, cpl, max) => Math.min(max, Math.max(1, Math.ceil(String(t || '').length / cpl)));
function cxTribLinhas(obj, teor, cpl, budget = 4) {                       // → { ol, tl }
  const ol = cxLn(obj || 'Objeto não definido', cpl, 2);
  if (!teor) return { ol, tl: 0 };
  return { ol, tl: Math.max(1, Math.min(cxLn(teor, cpl, 3), budget - ol)) };
}
function cxNotasCabem(notes, cpl, budget = 4) {                            // → { shown:[{t,l}], rest }
  const cap = notes.length === 1 ? 3 : 2;
  const pick = (b) => { const out = []; let used = 0;
    for (let i = notes.length - 1; i >= 0; i--) {                         // da mais recente para a mais antiga
      let l = cxLn(notes[i], cpl, cap);
      if (used + l > b) { if (out.length) break; l = b; }
      out.unshift({ t: notes[i], l }); used += l; }
    return { shown: out, rest: notes.length - out.length }; };
  const r = pick(budget);
  return r.rest ? pick(budget - 1) : r;                                    // "+N notas anteriores" ocupa 1 linha
}
/* Orçamentos por largura DA LISTA. CxIntimList mede o .cx-it-list com um único ResizeObserver e passa `L` para cada linha
   (nada de observer por linha). cpl = caracteres por linha da zona, estimativa conservadora. */
const CX_BUD = {
  wide: { cplTr: 80, cplNt: 66, budTr: 4, budNt: 4 },     // ≥ 1480 px: zonas lado a lado
  mid:  { cplTr: 100, cplNt: 100, budTr: 3, budNt: 3 },   // 860–1479 px: empilhadas
  mob:  { cplTr: 46, cplNt: 44, budTr: 4, budNt: 3 }      // < 860 px
};
const cxBudOf = (w) => w >= 1480 ? CX_BUD.wide : w >= 860 ? CX_BUD.mid : CX_BUD.mob;

Se preferirem zero estimativa, dá para usar clamps fixos (objeto 2, teor 2, nota 2 e max-height de 4 linhas na zona): o custo é cortar a 3ª nota no meio quando ela for longa. As constantes acima foram calibradas contra este mockup (Geist 12–12,5 px ≈ 6,1–6,4 px por caractere); ajustem olhando a lista real.

  • CxProc é chamado por Quadro, Hoje, Mesa de trabalho, Foco e Visão geral: o número passa a ter 25 caracteres em vez de 20 dígitos; confira truncamento nos cartões estreitos do Quadro (.cx-b-row).

  • Foco por teclado: o chip da operação, o botão do número e o ícone da peça continuam tabuláveis e com stopPropagation; Enter na linha só abre a gaveta quando e.target === e.currentTarget, como hoje.

9.5 · Acessibilidade mínima

  • Foco visível: a linha (role="button" tabIndex=0), o chip da operação, o botão do número e o ícone da peça têm o anel 2px --cx-accent do app (.cx :focus-visible), com outline-offset:-2px na linha para o overflow:hidden da lista não cortar.
  • Nada só no hover: toda informação está na tela. O title (texto completo do objeto, da decisão e das notas) é complemento; o caminho por teclado para o texto inteiro é Enter → gaveta.
  • Cor nunca é o único sinal: o alerta de embargos sempre traz texto ("Emb. 13/10 · 2 du", "Emb. HOJE") e a decisão sempre traz o rótulo "DECISÃO"; o chip tem aria-label por extenso ("Embargos de declaração até 13/10, 2 dias úteis").
  • Contraste: todos os textos miúdos da proposta passam de 4,5:1 nos dois temas (números na seção 10). O eyebrow da operação tem 10 px em caixa-alta: é o menor texto da linha e usa --mini.
  • Movimento: nenhuma animação.

Onde esta direção é pior que as outras

  • Piso mais alto. Uma intimação sem notas, sem teor e sem esteira ocupa ~64 px, contra ~57 px hoje (CLICKLOG, medido acima; a atual tem o selo "Atualizada" de 22 px na linha da parte): a identidade (operação, parte, processo) e o prazo (data, contagem, pé) têm, cada um, 3 linhas fixas. Densidade é a virtude que o pedido manda manter; esta é a direção que mais a aperta nas linhas simples. Nas ricas ela empata ou ganha: mostra mais (todas as notas, decisão) na mesma altura.
  • A zona de notas fica vazia onde não há nota. No mockup 3 das 11 linhas não têm nota (e ele foi montado com casos ricos; no acervo real a proporção sem nota tende a ser maior). A faixa dourada contínua deixa isso legível, mas é um vazio grande no meio de uma tela de 1900 px. Estender o Tribunal sobre o vazio foi descartado: quebra o alinhamento que dá sentido às zonas.
  • Percurso do olho. Parte à esquerda e prazo 1500 px adiante. O hover da linha ajuda, mas a leitura "quem → quando" é a mais longa das opções.
  • Em ~1200 px as zonas se empilham e a linha rica chega a ~130 px (SCALTECH, máximo medido acima): o ganho de usar largura desaparece justo onde ela falta; a média sobe para ~85 px (+16% sobre hoje).

Custos de manutenção e limites

  • Orçamento de linhas por estimativa de caracteres. O clamp CSS protege, mas a distribuição (quem fica com 1 ou 2 linhas) é heurística e precisa de ajuste fino por largura.
  • Sem expansão inline. Teor longo e 3ª nota longa só se leem inteiros na gaveta (clique + painel de 600 px cobrindo a lista). Há title com o texto completo, mas é recurso de mouse; a leitura por teclado depende da gaveta.
  • Identidade apertada. 340 px comportam ~44 caracteres de parte; "SCALTECH-COMERCIO IMPORTACAO E EXPORTACAO LTDA" perde o final (tooltip). A classe quase sempre trunca ("Incidente de Desconsi…"); uma tabela de siglas (IDPJ, EF) resolveria, mas é decisão de domínio.
  • Pé lotado. Embargos + peça + 2 glifos em 196 px: "du" no lugar de "dias úteis" e sem texto extra para "depois do final" (só tooltip).
  • Container queries exigem Chrome/Edge 105+ e Safari 16+; ok para o público do Apps Script, mas é a primeira vez que o app as usa.
  • Contraste. O app usa --cx-ink-3 (3,9:1 sobre branco no tema claro) em textos de 10,5–11,5 px. Aqui criei --mini (68% ink-3 + 32% ink): 6,4:1 no claro e 8,0:1 no escuro, também sobre a faixa das notas. O âmbar do chip de embargos (--emb-warn) tem 5,7:1 e o laranja do HOJE com texto sólido 5,3:1 no claro (hoje o --cx-yellow puro sobre --cx-yellow-soft dá 4,2:1). Vale adotar --mini no app inteiro, mas é mudança separada.

Premissas assumidas no mockup

  • Tema escuro = Noite (azul-marinho do app). No app, "Ardósia" é o tema claro base; os escuros são Noite e Grafite. Os tokens vêm de src/Nexus.shell.html ~3907 e ~3947.
  • Dias úteis consideram feriados nacionais (07/09, 12/10, 02/11, 20/11, 25/12), o que reproduz exatamente as datas de embargos do pedido (09/09, 15/10, 13/10, 20/10, 21/10). Por isso as contagens saem um pouco menores que as do pedido: RUBENS PAES mostra "2 du" (9/10 e 13/10; 12/10 é feriado) e não "3 du", CLICKLOG "8 du" e não "9". Continuam nas mesmas faixas.
  • teor e teorSrc são nomes provisórios; todos os textos de decisão do mockup são inventados.
  • Para a lista "Resolvidas", o app agrupa por data de atuação ("Últimos 7 dias") e só a mostra ao trocar o filtro para Resolvidas; aqui ela aparece como último grupo, aberto, para exibir o estado.
